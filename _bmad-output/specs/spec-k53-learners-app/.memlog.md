- (capability) CAP-1: Admin authors multiple-choice tests via Admin Panel that mimic the computerised K53 learner's test format; success=admin can create/publish a test consumable by the API
- (capability) CAP-2: Admin imports existing tests via CSV or JSON; success=a well-formed CSV/JSON becomes a stored test with questions, options, correct answers
- (capability) CAP-3: Road-sign catalog pre-loaded with official legislation codes; success=all official signs present, each linked to its legislation code, referenceable by test questions

- (capability) CAP-5: Flutter app lets learner take a test scoped to a single code (1/2/3) or any combination incl. all three; success=learner picks code(s) and receives a matching test
- (capability) CAP-6: Test-taking flow simulates the real computerised test closely (structure, scoring, pass/fail result); success=completed attempt returns a per-section score and pass/fail mirroring official rules

- (constraint) Road signs must be stored with their official legislation codes, not ad-hoc labels
- (constraint) Question selection/order randomised per attempt (no fixed sequence)
