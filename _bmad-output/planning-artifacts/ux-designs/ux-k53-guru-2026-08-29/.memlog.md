- (decision) Learner app north star: effortless, seamless, zero-hassle. So simple a 7-year-old can navigate it. Portrait-only orientation. Large, highly readable text (Anton hates small/hard-to-read UI)
- (decision) Persistent practice sessions that resume EXACTLY where left off across app minimise, phone lock, battery death, AND a different device. Session state synced to cloud keyed to the UUID profile. Practice is one continuous session: do 3 questions on a smoke break, come back later, nothing lost
- (decision) Practice mode has 4 persistent, independently-resumable states/tiles: (1) Randomized Training, (2) Rules of the Road, (3) Road Signs, (4) Vehicle Controls. Each keeps its own progress
- (decision) Profile (UUID) is a progress home: shows how far you've come and how many answered correctly from the question bank. Progress visualisation is a first-class priority, per-section progress shown
- (decision) Fun / dopamine is a design goal: sound effects on correct/incorrect are very important; progress display on the profile is very important. 5-minute quick-jump sessions that don't get boring
- (decision) Accessibility is KEY (consumer-grade): large legible text, high readability, support for visually impaired users, and a TTS reader to help people with reading difficulties
- (assumption) Form-factor: learner app is mobile Flutter, portrait-only; admin is Blazor web (separate surface, addressed after the learner app)
- (event) Stakes classified: consumer (public SA learners), accessibility-critical
- (question) BED DOWN: mechanics of 'Randomized Training' — does it draw across all three sections (weighted like the real test?), and is it scoped to a chosen code (1/2/3) or code-agnostic? How does code selection fit the learner app?
- (decision) Code selection happens at PROFILE CREATION and is changeable later in the profile. During practice/test the learner carries ZERO cognitive load about vehicle types/test categories - the code is set once and everything filters to it silently
- (decision) Randomized Training mirrors the real exam RATIO, random within that ratio, as a continuous rolling pattern - e.g. 2 Rules, 2 Signs, 1 Control, then repeats 2 Rules / 2 Signs / 1 Control, endlessly. Stays in warm Practice mode (feedback, no pressure)
- (question) JAD SESSION NEEDED: when a learner changes their code in the profile, how is existing progress/session data handled (migrate? reset per-code? keep per-code silos?). Cross-surface data-model decision, defer to a JAD
- (event) Resolved Randomized Training + code-selection open items
- (decision) Answer interaction: tap-to-select then CONFIRM (no instant submit - avoids accidental taps and lets the learner think). Confirm button sits at the bottom, greyed/disabled until an option is selected
- (decision) Correct answer: smooth green pulse + celebratory Lottie animation + haptic feedback + a tone that rises higher with each streak increment. Fun and rewarding
- (decision) Wrong answer (FINAL, supersedes earlier 'break' idea): gentle, never punishing - red highlight on the chosen option, green highlight on the correct one, NO haptic, no anxiety-inducing animation. Haptic is reserved for CORRECT answers only
- (decision) Streak counter included (Anton: brilliant). Drives the rising audio tone; celebratory not punishing
- (decision) Profile progress home shows ALL of: per-section mastery as green progress bars, % of the question bank mastered, a readiness 'you'd pass' meter, and streaks/best runs. XP awarded for every correct answer, with MORE XP from actual tests than from practice
- (decision) Accessibility line on feedback: celebratory but never punishing; wrong answers must not induce anxiety. Consistent with 7-year-old-usable + accessibility-key goals
- (decision) Test mode: countdown timer VISIBLE, but only on real tests (never in practice). Zero feedback during a test (no green/red/sound/why). Back-navigation ALLOWED - learner can revisit and change answers, like the real CLLT
- (decision) Test result screen is comprehensive: per-section pass/fail, overall pass/fail, and a per-code breakdown for combined tests (mirrors CLLT per-code partial-pass grading)
- (decision) First-run onboarding: a big friendly 'Start learning' CTA. The UUID is generated silently in the background - no upfront UUID hassle. It is surfaced later, in the profile
- (decision) UUID is visible in the profile and copyable, with a note like 'To save your progress, copy this UUID to import your results in another app'
- (override) LOCKED: profile linking/transfer uses QR CODES ONLY (QR encodes the UUID). No manual paste flow. Supersedes earlier 'paste a UUID' framing
