Best takeaways

“The admin panel's real user is Oom-the-examiner, not the product owner.”
The reframe that reshaped CAP-1, CAP-2 and the whole authoring surface.
The combination test is one booking, graded per code — with partial passes.
Anton's LL1 memory + the CLLT spec overturned our monolithic-ticket model. Pass Code 1, fail Code 3, keep the bike licence, re-test only the truck.
Two deliberate modes: warm Practice, cold Test. The contrast is the pedagogy.
Rehearses the emotional shift of the real day, not just the questions.

The spec that grew — 9 capabilities

  • CAP-1Admin authors K53-format tests
  • CAP-2Import tests via CSV / JSON
  • CAP-3Road-sign catalog with legislation codes
  • CAP-4API randomises per attempt (intra-section)
  • CAP-5Single code or valid combination sitting
  • CAP-6Faithful CLLT simulation, per-code result
  • CAP-7Import validation — reject broken rows
  • CAP-8Practice mode vs Test mode
  • CAP-9Anonymous self-custodied UUID profile
